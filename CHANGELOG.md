## v1.4.0 — Нормальное приложение: главное окно, фон, голос, ярлыки
- **Главное окно** (`app_window.py`): навигация слева (Главная / История / Расписание / Настройки /
  Проверка системы), на главной — поле команды, кнопка «Голосом», примеры-подсказки, статус
  Gemini/голоса/локальной модели и последние действия. Всё видно сразу, не нужно искать в меню трея
- **Работа в фоне**: крестик сворачивает окно в трей, программа продолжает работать; двойной клик
  по значку или повторный запуск ярлыка показывает окно (`single_instance.py` теперь "будит"
  работающий экземпляр через локальный сокет, а не молча ничего не делает); автозагрузка
  стартует сразу в трее (`--background`); выйти — отдельная кнопка в окне и в меню трея
- **Окна результата больше не закрываются сами**: окно автопилота закрывалось через 8 секунд,
  окно выполнения плана — через 1,8 с. Теперь остаются, пока не нажмёшь «Закрыть»; блокировка
  команд при этом снимается сразу — следующую команду можно запускать
- **Меню трея**: эмодзи, разделители, подменю «Ещё», действие по двойному клику
- **Голосовые команды**: любая неудача (нет PyAudio, микрофон закрыт Windows, тишина, речь не
  разобрана, нет интернета) раньше молча возвращала пустую строку — казалось, что голос "просто
  не работает". Теперь показывается понятная причина; перед записью — уведомление «Слушаю…»;
  реальная проверка микрофона (не "PyAudio установлен?", а "устройство видно?") на главной, в
  настройках и в проверке системы; язык голоса выбирается (русский / українська / English)
- **Ярлык не создавался**: скрипт записывался в UTF-8 (Windows Script Host ждёт UTF-16 — с
  кириллицей ломался), а путь `~\Desktop` неверен при включённом OneDrive. Новый `shortcuts.py`
  спрашивает настоящие папки у Windows, проверяет, что файл появился, и показывает причину ошибки.
  Ярлыки — на рабочий стол и в меню Пуск; создаются в установщике и из Настроек; `uninstall.bat` их убирает
- **Установщик**: в конце галочки (ярлыки, автозапуск); при ошибке окно не закрывается молча
- **Архитектура интерфейса**: один корень Tk в главном потоке, все диалоги — его дочерние окна;
  рабочие потоки обращаются к интерфейсу через `ui_thread.py` (раньше каждое окно создавало
  собственный `tk.Tk()` в своём потоке — для постоянного окна такая схема непригодна)

## v1.3.0 — Автопилот: нормальная навигация по экрану
Главная проблема — ассистент "не понимал, куда нажимать" — оказалась архитектурной, а не
"плохим ИИ": по одному скриншоту составлялся весь план кликов, а после первого же клика
экран менялся, и остальные координаты указывали в никуда.
- **Автопилот** (`agent_loop.py`): замкнутый цикл "скриншот → ОДНО действие → проверка,
  изменился ли экран → новый скриншот". ИИ видит результат каждого шага и исправляется
- **Правильные координаты**: Gemini работает на нормализованной сетке 0–1000, а не в
  пикселях. Промпт теперь это задаёт явно, программа пересчитывает в реальные пиксели.
  (Прежний "фикс масштаба" v1.2 предполагал пиксели и был неполным — заменён)
- **Русский ввод**: `pyautogui.write` молча пропускал кириллицу; текст с не-ASCII символами
  теперь вставляется через буфер обмена (прежний буфер восстанавливается)
- Новые действия: двойной клик (открыть папку), правый клик, прокрутка, пауза
- Защита от застревания: три одинаковых действия подряд / экран не реагирует на три клика /
  лимит шагов (`agent_max_steps`, по умолчанию 15) — остановка вместо клика вслепую
- Подтверждения: один раз на запуск автопилота (простые "открой сайт" — само через 3 с);
  опасные шаги (файлы, установка) спрашиваются отдельно КАЖДЫЙ раз; текст с экрана
  считается данными, а не командами (защита от инъекций через страницы/письма)
- **Модель по умолчанию `gemini-3.5-flash`** (бесплатна, заметно умнее `lite`); старые
  настройки мигрируют; имя модели меняется в Настройках. Устаревшая модель (404) теперь
  даёт понятную ошибку, а не загадочную
- **Ротация ключей исправлена**: обычный HTTP 400 больше не считается "ключ недействителен"
  и не выкидывает рабочий ключ из ротации (раньше — навсегда до перезапуска)
- **Строже валидатор**: лишние параметры, `True` вместо числа, диапазоны прокрутки/паузы
- **Темы**: светлая / тёмная / как в Windows (Настройки → Тема); `theme.py` отдаёт цвета
  динамически, остальной код менять не пришлось
- **`build_exe.bat`** + `app_paths.py`: настройки/история `.exe` хранятся рядом с ним
  (а не во временной папке PyInstaller); автозагрузка понимает `.exe`
- Мелочи: красный статус ошибки в трее раньше сразу затирался зелёным и никогда не был
  виден; `pyaudio` вынесен из requirements.txt (его сбой ронял всю установку); в
  установщике проверяется ошибка распаковки КАЖДОГО файла, а не только `main.py`
- Проект перенесён в видимую папку `outputs/ai_assistant`; сборка установщика — `tools/`

## v1.2.0 — Фикс приватности, точности кликов и надёжности (по итогам независимого code review)
- **Приватность**: команда пользователя и summary больше не попадают в
  `action_log.txt`/`history.json` как есть — перед сохранением через
  `privacy.py` маскируются фрагменты, похожие на пароль/PIN/токен/ключ
  ("введи пароль 12345" -> "введи пароль: <скрыто>"). Реальный текст
  по-прежнему уходит в ИИ без изменений — маскировка только для
  сохраняемых логов/истории
- **Точность кликов**: скриншот для Gemini уменьшается до 1280px, но
  раньше координаты клика применялись как есть — на мониторе шире 1280px
  (то есть почти на любом) клики были систематически смещены.
  `screen_utils.take_screenshot()` теперь возвращает ещё и коэффициент
  масштаба, `main.py` пересчитывает координаты в реальные перед кликом
- **Валидатор плана значительно строже** (`plan_validator.py`): проверка
  диапазона координат клика (в пределах экрана, не NaN), максимальной
  длины текста, допустимых клавиш для `press_key`/`hotkey` (и их
  количества), корректности URL (только http/https, блокирует
  `javascript:`/`file:`/`data:` и подобное), размера содержимого для
  `create_file`, того что `steps` вообще является списком
- **`open_app` пересмотрен по риску**: авто-подтверждение теперь только
  для явно безопасных программ (браузеры, блокнот, калькулятор,
  проводник) — всё остальное требует обычного клика, не полного доверия
- **Одна команда одновременно**: блокировка (`_command_lock`) не даёт
  запустить несколько команд параллельно при двойном нажатии горячей
  клавиши или совпадении с запланированной задачей
- **Один экземпляр приложения**: `single_instance.py` не даёт запустить
  вторую копию, с автоматическим восстановлением после сбоя (зависший
  лок от мёртвого процесса не блокирует новый запуск)
- **Атомарная запись JSON** (`atomic_io.py`, temp-файл + `os.replace`)
  для settings/history/расписания — файл не может повредиться при сбое
  или гонке двух потоков

## v0.5 — "Понемногу отовсюду"
- **Проверка результата клика**: после каждого клика локально (без лишних
  запросов к ИИ) сравниваются скриншоты "до/после" — если экран визуально
  не изменился, шаг помечается ⚠️ вместо ✅ (эвристика, не гарантия)
- **Правка плана перед подтверждением**: у каждого шага своя галочка,
  можно вычеркнуть один шаг, не отменяя весь план
- **Безопасность**:
  - Ключи Gemini переехали из открытого settings.json в защищённое
    хранилище Windows (Credential Manager) через `keyring`, с тихим
    откатом на файл, если хранилище недоступно (`secure_store.py`)
  - Пароли/PIN/коды доступа помечаются ИИ как "sensitive" и не попадают
    в логи и окно подтверждения (видно только "•••••••")
- **Нативные Windows-уведомления** (Центр уведомлений) вместо всплывающих
  окон tkinter — не перехватывают фокус (`notifications.py`, `winotify`)
- **Расписание задач** (`scheduler.py`): "по таким-то дням, в такое-то
  время — выполни команду", с окном управления в трее → Расписание;
  каждая задача всё равно идёт через обычное подтверждение
